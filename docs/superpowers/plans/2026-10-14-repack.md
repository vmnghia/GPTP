# Repack Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One Repack command in the Manifold Editor that puts a new `GPTP.qdp` into FireGraft's exe and adds the to-repack folder's files to its MPQ, replacing FireGraft and PyMPQ for repacking.

**Architecture:** A pure reader/writer of FireGraft's exe layout (`FireGraftExe`), a pure scan of the to-repack folder and an orchestrator (`Repack`) in Manifold.Core, both tested on Linux with fake exes; StormLib adds the files through a host interface; the WinUI window adds the dialog and the toolbar button.

**Tech Stack:** C# / .NET 8, xUnit, StormLib (via `Manifold.Storm`), WinUI 3 written in code (no `.xaml`).

**Spec:** `docs/superpowers/specs/2026-10-14-repack-design.md`

## Global Constraints

- FireGraft's header: six u32 at the end of the launcher's last section: `"PEGF"` (u32 `0x46474550`), 1, 1, plugin id, plugin size, 0. 24 bytes. The plugin follows at once.
- After the plugin: zeros to the next 512-byte boundary, then `MPQ\x1A`. The MPQ is copied byte for byte.
- A plugin must be a 32-bit DLL: PE machine `0x14C`, file characteristics with `IMAGE_FILE_DLL` (`0x2000`).
- The plugin id in the header is kept from the exe (GPTP's `0x1B4D69B6`).
- Defaults: plugin `<exe folder>\GPTP.qdp`; to-repack folder `<exe folder>\to-repack\`; both overridable per exe in the editor's settings.
- Repacked files: every file in a subfolder of the to-repack folder, under its relative path with `\`, except `*.bak`; added PKWARE-imploded (`StormArchive`'s existing `Add`).
- Protected paths and their warnings, shown when the to-repack copy differs from the exe's: `rez\stat_txt.tbl` "would replace the strings saved by the editor"; `Manifold\buttonsets.bin` "would replace the editor's button sets".
- The swap keeps the previous exe as `<exe>.bak`; the work copy is `<exe>.repacking`.
- The window has no `.xaml`; it compiles on Linux with `dotnet msbuild -restore -t:Compile -p:WindowsAppSDKSelfContained=false` in `ManifoldEditor.App/`.
- Tests: `dotnet test tools/ManifoldEditor/Manifold.Core.Tests` (119 pass before this plan).

## Review Focus

1. A leftover `<exe>.repacking` from a crashed run: overwritten, never swapped in as is. (Task 3 test.)
2. An exe without FireGraft's header (a plain MPQ exe): the status line says so, files-only Repack works, a plugin repack is refused with nothing changed. (Tasks 1 and 3 tests.)
3. The plugin file missing, or not a DLL (a half-written build): a clear problem, nothing changed. (Task 2 test.)
4. The to-repack folder missing or holding only top-level files: an empty list, and Repack can still pack the plugin. (Task 2 test.)
5. Nested to-repack paths: MPQ paths use `\` at every depth (`unit\terran\x.grp`), whatever the OS separator. (Task 2 test.)

[Fact] public void Parses_the_users_layout()
{
    var plugin = Make.Dll(extra: 1000);
    var exe = Make.FireGraftExe(plugin);
    var layout = FireGraftExe.Parse(exe)!;
    Assert.Equal(0x2400, layout.HeaderOffset);
    Assert.Equal(0x1B4D69B6u, layout.PluginId);
    Assert.Equal(0x2400 + 24, layout.PluginOffset);
    Assert.Equal(plugin, layout.Plugin(exe));
    Assert.Equal(0, layout.MpqOffset % 512);
    Assert.Equal("MPQ\x1A"u8.ToArray(), exe[layout.MpqOffset..(layout.MpqOffset + 4)]);
}

[Fact] public void A_plain_exe_has_no_header() =>
    Assert.Null(FireGraftExe.Parse([.. PeImageTests.MinimalExe((_, _) => { }), .. Make.Mpq()]));

[Theory]
[InlineData("count", 2u, 0u)]       // two plugins: layout unknown
[InlineData("reserved", 1u, 1u)]    // non-zero last field
public void Refuses_other_headers(string what, uint count, uint reserved)
{
    var e = Assert.Throws<InvalidDataException>(() => FireGraftExe.Parse(Make.FireGraftExe(Make.Dll(), count: count, reserved: reserved)));
    Assert.Contains(what, e.Message);
}

[Fact] public void Refuses_non_zero_padding()     // a byte between the plugin's end and the MPQ set to 1
[Fact] public void Refuses_an_MPQ_elsewhere()      // the MPQ moved 512 bytes on (512 more zeros): message contains "MPQ"
[Fact] public void Refuses_a_user_data_header()    // MPQ\x1B in place of MPQ\x1A: message contains "user-data"

[Theory, InlineData(5000), InlineData(0)]
public void Packs_a_larger_and_a_smaller_plugin(int extra)
{
    var exe = Make.FireGraftExe(Make.Dll(extra: 2000));
    var old = FireGraftExe.Parse(exe)!;
    var plugin = Make.Dll(extra: extra, fill: 0xAB);
    var result = FireGraftExe.WithPlugin(exe, plugin);
    var layout = FireGraftExe.Parse(result)!;
    Assert.Equal(plugin, layout.Plugin(result));
    Assert.Equal(exe[..old.HeaderOffset], result[..layout.HeaderOffset]);           // launcher unchanged
    Assert.Equal(exe[old.MpqOffset..], result[layout.MpqOffset..]);                 // MPQ byte for byte
    Assert.Equal(old.PluginId, layout.PluginId);
}
